# @sqlite-host/playground

A browser playground for SqliteHost, in the spirit of
[typespec.io/playground](https://typespec.io/playground): type a `.tsp`
host definition on the left, watch the manifest, schema DDL, and
generated C#, Java, and TypeScript update on the right.

Everything runs in the page. The TypeSpec compiler, the SqliteHost
decorator library, and all four emitters are bundled into `bundle.js`;
there is no server and the page makes no network requests.

```bash
pnpm --dir typescript/playground run build:web
# then serve web-dist/ with any static file server, e.g.
python3 -m http.server --directory typescript/playground/web-dist
```

## How it compiles without a file system

`@typespec/compiler` reads sources through a `CompilerHost` interface,
so the only thing standing between it and a browser is where the bytes
come from. Three pieces make it work:

- **`scripts/gen-vfs.mjs`** (build time) snapshots every `.tsp` the
  compiler needs — its own `lib/` std library, `@sqlite-host/typespec`'s
  `lib/`, and both `package.json` files — into `src/generated/vfs.json`,
  along with the sample host definition that prefills the editor.
- **`src/browser-host.ts`** serves that snapshot plus the one file the
  user is editing. Decorator implementations never come from the
  virtual file system: they are statically imported modules handed back
  from `getJsImport`.
- **`src/pipeline.ts`** feeds the host to `compileHostLibrary`, which
  takes an optional `CompilerHost` (defaulting to the Node host) for
  exactly this reason, and then runs the ordinary emitters over the IR.

Because only the host differs, the browser output is the same bytes the
CLI writes. `src/test/parity.test.ts` pins that against the committed
goldens — the same ones `tests/cross-language-golden/run.mjs` uses.

## Build output is not committed

Both `web-dist/` and `src/generated/` are ignored, in the **project
root** `.gitignore` rather than a package-local one like
`typescript/sample-admin/.gitignore` uses, since two entries for one
package do not warrant a second file.

This is the deliberate difference from `sample-admin`, whose bundle is
small and self-contained: this bundle embeds the entire TypeSpec
compiler and weighs roughly 2 MB, and `src/generated/vfs.json` is a
verbatim copy of files that already exist in `node_modules`. Both are
regenerated by `pnpm run build:web`, so committing them would only add
review noise and drift.

## Bundling notes

`scripts/build-web.mjs` follows `sample-admin`'s esbuild pattern with
two necessary differences, both explained in the file:

- `platform: "browser"` instead of `"neutral"`, because
  `@typespec/compiler` ships a `browser` field that swaps its Node host
  and console sink for browser builds. Without it esbuild ignores that
  map and tries to bundle `node:fs`, the language-server transport, and
  prettier.
- an `alias` for `node:path` → `src/browser-node-path.ts`, the one Node
  builtin left in the graph (the shared codegen frontend imports
  `resolve`). It implements the real POSIX algorithm and throws for the
  one case a browser genuinely cannot serve — a relative path, which
  would need a working directory.

`src/browser-host.ts` deep-imports two of the compiler's internal
`tsp-index.js` modules. That is not incidental: the package's public
`$decorators` export drops `TypeSpec.indexer`, and without it no
array-typed model property compiles.

## Tests

```bash
pnpm --dir typescript/playground run test
```

- `parity.test.ts` — the in-memory pipeline reproduces the committed
  manifest, DDL, C#, Java, and TypeScript byte for byte.
- `diagnostics.test.ts` — broken sources surface diagnostics with
  `line:col`, never a thrown exception.
- `web-bundle.test.ts` — `build:web` produces a self-contained
  `bundle.js` + `index.html`, and the bundled pipeline runs.

## Browser tests

The tests above all run under Node, so none of them ever renders the
page. `e2e/` covers what only a real browser can answer — that the
module bundle loads and the page fetches nothing but itself, that the
prefilled sample compiles on its own into output byte-identical to the
committed manifest golden, that the tabs and the C# profile selector are
wired to what they claim to show, and that a broken source surfaces a
`line:column` diagnostic and recovers after one debounced recompile.

```bash
pnpm --dir typescript/playground run build:web   # e2e/ serves web-dist/
pnpm --dir typescript/playground run test:e2e
```

It is a separate script from `test` on purpose: the unit suites must
stay runnable without a browser. `tests/end-to-end/run-all.sh` runs both.

Chromium is expected to be **already installed** — this environment and
CI provision it and point `PLAYWRIGHT_BROWSERS_PATH` at it, so
`playwright install` is never run here and installs use
`PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1`. That is why `@playwright/test` is
pinned to an exact version rather than a caret range: each release
expects one Chromium revision (1.56.1 → 1194), and a minor bump would
silently stop resolving the binary that is there. If a run reports a
missing executable, the fix is to align the pin with the installed
revision, not to download a second browser.
